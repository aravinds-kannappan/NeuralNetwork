We trained a simulated robot arm to move a cube using a fixed piece of a pretrained neural network. Then we changed that piece to ask what was actually helping.

The starting point was Abay’s Borrowed Geometry: can a network reuse structure learned before it ever sees the new task? Your longer-term question goes further: could several specialists inside a robot share useful information and cover for one another when something goes wrong?

This page follows the completed tests, explains what each measurement means, and separates observations from possible explanations. Three observations guide the story:

  1. The original pretrained layer and a control with randomized linear weights achieved the same success rate in the one complete comparison seed.
  2. Those two controllers succeeded on different attempts. A shared score hid potentially useful differences.
  3. The pretrained controller’s neuron response patterns stayed very similar during training on a fixed panel of robot states.

The study stopped early. Five policies completed 600 evaluation episodes. Only one training seed has all four comparison methods. The remaining compute was cancelled at your request. The proposed team and alignment tests were not run. Run record

·The terms, on one robot

Imagine the arm at the start of an attempt. It has to pick up a cube and move it to a target. These seven terms describe the pieces involved.

Controller, or policy. A rule that turns what the robot knows now into its next action. Our learned controller reads numbers describing the arm, cube, and target, then produces movement and gripper commands.

Representation. An internal vector—a list of numbers—that the network uses to process a situation. Two controllers can describe the same physical situation using different internal vectors. Sharing the same vector length does not establish that the vectors mean the same thing.

Frozen layer and learned interface. “Frozen” means we keep that part’s numerical weights fixed. We train a small input interface to put robot measurements into the layer, and an output decoder to turn its response into actions. The interfaces can learn even though the middle part stays fixed.

Demonstration. An example of how to act. A scripted expert generated robot trajectories. We trained the controller to imitate the expert’s commands. This procedure is called behavior cloning.

Training seed and test episode. A training seed sets the random choices used to train one controller. A test episode is one attempt by that controller to move the cube. Sixty test episodes from one trained controller are not sixty independently trained controllers.

Checkpoint. The saved weights at a particular training step. We selected a checkpoint using separate validation examples, then tested it on robot episodes that were not used for training or selection.

Control. A comparison designed to test an explanation. For example, if a randomized layer works as well as the original one, we must ask whether the original pretrained matrix structure was responsible for the score.

What does “geometry” mean here? How a network arranges and transforms vectors of numbers. The research question is whether structure from earlier learning helps a new task. It does not simply mean the physical shape of the robot arm.

The definitions above describe this experiment. Exact input fields and model operations are in the executed code.

0What the robot learned

The task: move a cube to a target in a physics simulator. Each control step starts with a measurement of the current situation and ends with an action. The robot gets another measurement after it moves, and repeats the process.

We borrowed one internal block, layer 26, from the public Gemma 4 31B model. We kept its weights fixed and trained the small interfaces around it. The diagram shows the computation that actually ran. Select a part to see its job.

We used 16 training demonstrations and 32 separate validation demonstrations. Each evaluated controller got 60 attempts at familiar targets and 60 at shifted targets. Familiar targets stay near the demonstrated region; shifted targets move farther sideways.

Technical detail: input features, optimization, and checkpoint selection

The observation is a 21-dimensional privileged state vector: joint positions, effector position and yaw encoding, gripper opening/contact, cube position and yaw encoding, and target position. Features are normalized with training-set means and standard deviations, with a standard-deviation floor of 0.05. There is no camera perception model.

The policy uses a 21→5,376 linear encoder, affine LayerNorm, the frozen block, non-affine output LayerNorm, and a 5,376→5 linear decoder. The loss is continuous-action MSE plus 0.25 times binary cross entropy for gripper direction.

AdamW ran for 1,000 steps at learning rate 0.0003, batch size 128, weight decay 0.0001, and gradient clipping 1.0. Validation checkpoints were steps 0, 100, 250, 500, 750, and 1000. The minimum validation loss selected the evaluated policy. Test success did not select the checkpoint.

Training resets: 1000–1015. Validation resets: 2000–2031. Familiar test resets: 30000–30059. Shifted test resets: 40000–40059. The additional validation trajectories mean this is not a strict 16-episode total-data budget. Configuration · Protocol

Technical detail: which Gemma computation was verified?

The pinned model is google/gemma-4-31B revision 5bbc2fb1…, layer 26. The extracted block matched the official implementation on the logged three-input numerical check. Frozen parameter hashes were unchanged for each completed frozen-model training run.

The input contains one state token and no past-token cache. Attention has only one token to attend to, so its softmax is one and Q/K cannot affect the output. This is not a test of an attention-copy mechanism. The public model revision is multimodal; these experiments cannot attribute robot control to text-only pretraining. Extraction and numerical check

1Testing the frozen layer

The question: does the original pretrained matrix structure help more than a changed version of the same block?

We compared four controllers. The pretrained version uses the original matrices. A randomized version replaces their entries while matching their average and spread. A scrambled version rearranges their rows and columns. A small conventional neural network provides another baseline.

ObservedThe original and randomized versions tied in the complete comparison seed. Both completed half of the familiar-target episodes, and far fewer shifted-target episodes. Switch the target condition below to see the difference.

InterpretationA large fixed collection of transformations may help this low-data task even when its original matrix structure is disrupted. That is an explanation to investigate, not a mechanism we have isolated.

The second pretrained controller, trained with seed 1337, completed 25/60 familiar-target and 8/60 shifted-target episodes. Its comparison controls did not finish. We keep it separate rather than averaging two pretrained seeds against one control seed. Per-seed results

Technical detail: what the controls preserve

Randomized linear matrices. Each matrix is replaced with Gaussian weights matched to its original mean and standard deviation. Pretrained normalization vectors and the layer scalar remain. This is not a completely random model.

Scrambled matrices. Independent row and column permutations preserve each matrix’s singular values, element values, and norms while disrupting how directions align between matrices. Normalization vectors and the layer scalar remain unchanged.

Small MLP. The fully trained 21→381→381→5 network has 155,834 trainable parameters. Frozen-layer policies have 155,909 trainable parameters plus 412,898,305 frozen parameters. We approximately match trainable counts, not total capacity or compute. Shared hyperparameters were not tuned separately for each method. Executed controls

Why the original paper’s score is not the comparison here. Borrowed Geometry reports a different robotics setup using offline reinforcement learning on play data. We used imitation of task-specific demonstrations, different interfaces, and a public model revision that does not exactly match the paper’s stated dimensions. We could not retrieve the original robot implementation or trained adapters. These results extend the question; they do not reproduce or refute that result.

2The same score, different failures

The question: if two controllers succeed equally often, do they solve the same attempts?

This matters for your robot-team idea. A backup can be useful when it handles situations the first controller cannot. Looking only at the overall score hides that difference.

ObservedOn familiar targets, both controllers succeeded on 18 episodes. The pretrained controller uniquely solved 12 more, and the randomized controller uniquely solved another 12. The grid shows the actual paired attempts. Select a square to inspect it.

InterpretationAt least one controller succeeded on 42/60 familiar-target episodes. A perfect selector with advance knowledge could choose those successes. A real system would have to detect trouble early, choose a better controller, and handle the state left behind by the first one. We have not tested any of those steps.

Technical detail: why the union is not an ensemble result

The union is computed after observing both complete rollouts from the same initial state. A switched controller would usually take over from a different, partly progressed state. It also needs a selection rule without access to the future outcome. Therefore, 42/60 is an oracle selection upper bound for these separately evaluated rollouts, not a measured recovery rate.

All these policies share one training dataset. Reusing reset seeds improves pairing, but does not create independent training replications. The episode grid is descriptive evidence from training seed 42. Saved rollouts

3Following neuron responses

The question: how much do a neuron’s responses change while the surrounding robot interface is trained?

A neuron produces a number for each input. We took the same 128 robot states at different checkpoints and collected each neuron’s 128 responses. Comparing those lists gives us a response “fingerprint.” A cosine close to 1 means the lists point in nearly the same direction.

Direction is only part of the story. If every response doubled, cosine could stay at 1. We therefore also compared response magnitude, and used a mean-centered cosine to reduce the effect of a common offset.

ObservedThe median centered cosine from initialization to the selected checkpoint was about 0.998. The frozen block’s parameter hash was unchanged. At the same time, the surrounding interfaces had been trained and the resulting controller completed robot tasks.

InterpretationThis is consistent with learning to use existing features. It does not establish that the decoder alone caused the successful behavior. Restoring the initial encoder while keeping the trained decoder would help test that explanation; we did not run that intervention.

Connection to Abay’s neuron study. A changing response does not, by itself, tell us which part of a network changed or whether a neuron gained a new semantic role. Identity, inputs, response scale, and behavior need separate checks. Our measurements are from Gemma robot controllers, not the lithium neuron or Abay’s original checkpoints. Technical detail: what exactly was compared?

For neuron j, the response vector contains its signed gated-MLP activation on each of the same 128 validation states. Raw cosine compares those vectors directly. Centered cosine compares each after subtracting its own mean; here it is Pearson correlation across states. The norm ratio is ‖alater‖₂ / ‖ainitial‖₂. We do not take a cosine between two scalar activations.

Neuron indices refer to fixed coordinates in the same extracted block. No positive/negative clipping or cross-model neuron matching is used. Hashes verify unchanged block parameters, but the learned encoder and input normalization can change the immediate inputs to that block even when physical states are held fixed.

The panel states come from validation trajectories and are correlated. We did not assign semantic labels to the neurons. Step 100 was selected by validation loss; step 1000 had worse validation loss and was not used for the reported robot scores. Audit code · Checkpoint losses

Prediction loss and behavior gave different rankings

The small network’s selected validation imitation loss was lower than pretrained Gemma’s: 0.15258 versus 0.17830. Yet its familiar-target success was also lower: 11/60 versus 30/60. Predicting expert commands on saved states and controlling a moving robot are different evaluations. This single comparison illustrates why the behavioral test matters. 4From one controller to a team

The work so far contains one simulated arm and separately evaluated controllers. The connection to your project is a testable next step: build specialists whose strengths differ, then measure whether they can exchange useful information and recover from each other’s failures.

One specialist might handle grasping; another might assess obstacles; a third might decide whether an action should continue. A shared layer or memory would be a component of that design. It would not, on its own, show that the specialists understand one another’s internal representations.

A proposed compatibility test: take two independently trained input interfaces around the same frozen layer. Feed the second interface’s representation to the first controller’s decoder. Measure whether control still works. Then fit an alignment using paired examples of the same robot states, and test whether that repairs any lost performance.

Prepared, not executed. The interface-exchange and alignment experiment exists as a draft script. It has no experimental results. We also did not train a mixture-of-experts router, evaluate multiple arms, or test collision safety. Unrun draft

Technical detail: alignment, expert routing, and self-improvement

The draft uses controllers with training seeds 42 and 1337, a fixed shared pretrained block, and 512 paired training states. It proposes rank-64 scaled Procrustes alignment, a shuffled-pair negative control, an own-controller rank-projection control, and a ridge-regression baseline. Fresh closed-loop evaluations would test whether alignment improves behavior, not only similarity.

A mixture-of-experts connection would be a gating or routing mechanism that chooses between specialists. In the proposed robot system, that choice must be evaluated under a shared action/time budget and realistic partial failures. The current oracle union is not such a router.

Sharing information or adapting during a task is not recursive self-improvement. That longer-term claim would require a system that helps change its own capabilities and demonstrates durable improvement under independent evaluation. No such loop was implemented here.

5Small tests that would matter

These are proposed experiments, ordered by what they could change about our interpretation. None was launched after the stop request.

  1. Finish the matched seeds. Complete the missing randomized, scrambled, and small-network runs for the remaining seeds. This tests whether the observed pattern is stable across training randomness. Repeating test episodes alone cannot answer that question.
  2. Separate fixed features from pretrained structure. Add controls that reset the normalization scales and compare fixed random features at the same width. If the advantage survives those changes, a more general feature-bank explanation becomes more plausible.
  3. Swap the learned components. Keep the trained decoder and restore the initial input interface; then do the reverse. Evaluate the same held-out physical resets. This tests which learned component the behavior depends on.
  4. Turn complementary failures into a real handover. Compare a progress-triggered switch with each individual controller and a random-switch control, using the same total action budget. Measure actual completion from the state at handover.
  5. Test representation exchange before building a larger team. Compare direct interface exchange, paired-state alignment, shuffled alignment, and simple regression on fresh robot resets. Better cosine or action prediction alone would not establish better coordination.

6Five questions for Abay

  1. Can you share the exact model revision, original robot adapters, input preprocessing, and data split so we can isolate why our randomized control can match the pretrained block in this setting?
  2. Does the claimed geometry advantage survive controls that preserve matrix singular values and normalization scales, and how sensitive is it to expert demonstrations versus offline play data?
  3. Have separately trained interfaces around one frozen layer been tested for exchanging hidden representations or action decoders, and does an alignment repair any failure?
  4. For the lithium-neuron checkpoints, can we compare identical examples with signed activations, raw norms, and fixed coordinate identity while separating upstream-input changes from neuron-weight changes?
  5. What signal might predict failure early enough for a useful handover, given that lower imitation loss did not predict better closed-loop success in our completed comparison?

7What we know, and the files

We have working learned controllers and controlled comparisons on recorded physical resets. The evidence supports more precise next questions. It does not yet establish that pretrained geometry is the cause of the observed control performance, or that a team of agents can recover from faults.

Technical detail: feasibility baseline, uncertainty, and stop history

An earlier small-network feasibility run used 256 demonstrations and 2,000 optimization steps, achieving 39/40 successes in each condition. It used different test reset seeds and more data/training. It establishes that this task is learnable, not a matched sample-efficiency comparison. Its run ID is recorded in the provenance file.

The first comparison run stopped after three complete models. A resumable run completed the small network for seed 42 and pretrained Gemma for seed 1337, then was cancelled at the user’s request. The random seed-1337 training was incomplete and has no reported evaluation.

We retain completed model outcomes from interrupted runs, but do not present the sweep as completed. All policies share one demonstration dataset; training-seed and episode-seed variation are different sources of uncertainty.
