Observation

Redundancy fixed command dropout.

The single controller succeeded in 0/30 dropout episodes. Each method with takeover succeeded in 30/30. All four methods succeeded in all 30 healthy episodes.

Interpretation: a live duplicate can replace this disabled command producer. This does not test a backup with different skills or whether learned experts make independent mistakes.

Observation

A duplicate inherited stale information.

With the shared pose publisher stopped, single and takeover both scored 0/30. Both refresh methods scored 30/30. When the refresh source also failed, every method scored 0/30.

Interpretation: access to fresh information explains the gain in this setup. Refresh occurs before a stale observation is used, so this is prevention of failure, not recovery from an already failed grasp.

Observation

Fewer calls depended on honest timestamps.

On honest stale-publisher faults, age-triggered refresh averaged 32.43 explicit calls versus 41.43 for periodic polling, with equal success. Healthy age-triggered control made no extra calls; periodic control averaged 41.43.

Interpretation: the trigger saves calls here. Calls have no simulated latency or energy cost, so this is not a measured real-time or energy saving.

Follow-up observation

False freshness reversed the practical choice.

With false current timestamps, age-triggered refresh made zero calls and scored 0/30. Periodic polling scored 30/30. It switched controllers in 1/30 episodes despite a functioning command producer.

Interpretation: trusted timestamps are a hidden dependency. An independently checked timestamp or limited periodic probing is a plausible next design; neither has been tested here.

Sources for all observations in this section: main run summary, follow-up summary, and episode records. Interpretations are inferences within the stated intervention design.

Why the bootstrap intervals are not used as certainty claims

The logged paired bootstrap differences collapse to [0, 0] or [1, 1] because every observed seed in these comparisons has the same binary difference. That is a small-sample boundary artifact, not proof of zero uncertainty. We report per-condition Wilson intervals instead: 30/30 corresponds to 88.6–100%, and 0/30 to 0–11.4%.

The 480 main episodes are not 480 independent task distributions. There are 30 paired reset seeds, one task, fixed fault timing and scripted interventions. The follow-up adds another 30 reset seeds, not new task families.

03 / The cosine result

High similarity concealed a large task-relevant error.

In all 30 stale-pose takeover episodes, at least one step had object-position error above 4 cm while whole-state cosine exceeded 0.99. The maximum cache error in each episode ranged from 6.4 to 16.0 cm.

For the recorded seed-100 example at 1.80 simulated seconds, the cached pose was 13.17 cm wrong while whole-state cosine was 0.999701. Pose-only cosine was 0.971059.

Exact derived values and frame-selection rule · Recorded traces. The illustrative frame is the largest logged error in the preselected seed-100 stale/takeover trace.

What this does and does not show

The vector concatenates joint angles, end-effector position, gripper opening/contact, object pose and target pose. It is an engineered, mixed-unit vector without whitening. Most coordinates match even when the object pose is wrong.

This demonstrates a metric-design failure in this representation. It does not show that learned robot embeddings, BSF blocks or Abay's neural representations fail the same way. The cosine diagnostic is offline and never selects a controller.

Connection to the checkpoint work: similarity alone does not settle function. Hold examples fixed, inspect scales and task-relevant directions, and compare actual behavioral outcomes. Our robotics result is an analogy with a concrete test harness, not an explanation of lithium-neuron changes.

05 / Methods and controls

A small, reproducible fault harness

  • Environment: cube-double-play-singletask-task1-v0, OGBench 1.2.2, MuJoCo 3.3.7, Python 3.12.13 on local CPU. One UR5e arm; two cubes; move the selected cube to its task goal. The task layout is fixed with ±1 cm x/y object jitter, random cube yaw and randomized initial arm state.
  • Controller: OGBench CubeMarkovOracle, duplicated with the same initialization. Both use fresh proprioception and the shared cached object pose/yaw. The oracle ignores its raw observation argument and uses the selected info fields; hidden diagnostic truth does not enter routing.
  • Timing: 20 Hz control, at most 250 actions (12.5 simulated seconds), faults from step 10. Takeover after five consecutive missing commands or 40 steps without at least 2 mm goal-distance progress. Age trigger and periodic poll interval are both one step. Up to 250 explicit refresh attempts are allowed per episode.
  • Information control: all methods have the same allowed observation interface and budget, but only refresh methods query it. Their success therefore includes an information advantage. Refresh calls consume no additional simulation steps. This is not an equal-information test of routing intelligence.
  • Primary outcome: the environment's success flag by the fixed horizon. Secondary outcomes include steps, refresh attempts, switches, and cached-pose error. Action bounds and finite values were checked; collisions, safety violations, hardware damage and real-time deadlines were not measured.
  • Pairing and checks: initial-state hashes match across methods for each seed. All three runs passed finite/bounded-action checks and exact repeat of one episode's success, step count, initial hash, final goal error and maximum cache error. These are selected replay fields, not a full bitwise trajectory comparison.
  • Follow-up: the false-timestamp condition was designed after the first comparison, then committed before evaluation on seeds 200–229. No policy thresholds were retuned on those results. It is an engineered stress test, not a measurement of natural fault frequency.

06 / What would change the interpretation next?

Four small, consequential tests

Not yet run

Vary the information fault.

Compare stale, fresh-but-wrong, noisy and missing poses at several grasp phases. Give all methods the same query and action budget. Test independent provenance checks and a bounded periodic probe against the age-only trigger.

Changes the interpretation if robustness disappears beyond one early, easy-to-detect fault.

Not yet run

Use genuinely different skills.

Keep observation quality fixed while comparing identical copies, distinct scripted approaches and learned policies. Measure backup success conditional on primary failure and joint failure on new layouts.

Changes the interpretation if diversity, rather than duplication or extra retries, explains recovery.

Not yet run

Calibrate similarity against outcomes.

Compare cosine in the current vector, centered/standardized state, task-relative coordinates and a learned embedding. Train any calibration only on development data. Evaluate controller choice against a fixed-backup and equal-budget outcome-history baseline.

Changes the interpretation if representation similarity predicts scene identity but not the next successful action.

Not yet run

Test an actual retained revision.

Let a diagnostic agent propose one coordinator edit; evaluate it with an independent critic and an untouched final set. Compare with equal-budget simple search. Save the executable diff and regressions.

Changes the claim from fixed fault tolerance to measured program improvement only if the retained revision generalizes.

What could not be verified: Abay's original trained robotics interface and exact checkpoint execution were not available in this pilot; his neural results were not rerun. Learned geometry, neural expert identity, collision safety, multi-arm handoff, language-agent coordination and recursive self-improvement remain untested.
