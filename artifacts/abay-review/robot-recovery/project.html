01 / The central question

Similarity may help agents share skills. Does it tell us who can take over?

Your team would separate grasp planning, execution, observation and supervision. Agents share a structured memory, while a coordinator assigns action ownership and chooses an available recovery controller.

The research target is behavioral substitutability: whether a backup succeeds in the situations where the primary fails. Similar representations, two copies of a controller, or a shared memory are possible ingredients; their usefulness must be measured.

Falsifiable hypothesis

Recovery history plus valid state beats similarity alone.

Retrieve similar past situations with cosine similarity, then rank eligible backups using measured recovery outcomes and memory freshness. Compare against nearest-neighbor routing and simple fixed recovery under equal budgets.

A useful negative result: cosine predicts familiar scenes but fails to predict recoverability after a shared observation error.

P(backup succeeds | primary fails, fault type, available observations)

Evaluate this conditional outcome alongside joint failure. A global embedding score is a diagnostic, not a certificate of recovery or safety.

02 / What connects this to Abay

Three findings, three testable extensions

Author-reported result

Frozen geometry can support robot control.

Borrowed Geometry connects frozen Gemma layers to trained task interfaces. On the selected cube task, it reports 60.22% ± 45.87 success across three training seeds for L26, versus 0.89% for random-initialized Gemma. The large seed spread is consequential.

Our extension: ask whether a shared frozen representation supports reliable routing between recovery skills, and whether shared representations also create correlated errors.

Borrowed Geometry, pp. 4–5. This is transfer evidence in that setup; it does not demonstrate agent teamwork or self-improvement.

Source-audited observation

A neuron's coordinate is not its permanent job.

The lithium visualization follows a fixed coordinate but independently selects top examples at each checkpoint. The onset work also follows fixed final-selected examples, which can miss transient roles. Weight-cosine sequences are already present in the public analysis.

Our extension: version memory encoders and evaluate the same robot situations across policy checkpoints. Track response profiles and behavior together, rather than labeling an expert by one salient activation.

Viewer extraction · Weight-analysis code · Definitions and onset methods.

Related evidence

A concept can occupy several directions.

Goodfire's block-sparse featurizers represent related variation together. Its curve example groups orientations that individual neurons or sparse features partition.

Our extension: compare a whole-layer embedding, a task-relevant subspace and explicit geometric state when retrieving recovery experiences. A block that preserves orientation might matter more than a high global similarity.

Goodfire's vision report · Paper, Figure 11. This motivates a hypothesis; it does not identify robot affordances or explain the lithium neuron.

Direct connection, bounded scope

Use the same simulator family first.

Abay's cube experiment uses OGBench manipulation. Its environment has a UR5e arm and Robotiq gripper. “Cube-double” means two cubes; task1 is a single pick-and-place task.

Our starting point: one simulated arm with several software roles. Two physical arms, learned expert diversity and neural routing are later extensions.

Arm environment · Cube task definitions. Our pilot uses OGBench's scripted oracle; it does not load Abay's trained interface or Gemma checkpoint.

03 / The proposed system

A team with explicit responsibilities

RoleResponsibilityWhat must be logged
ObserverEstimate object pose, obstacles and gripper state.Source, timestamp, coordinate frame, uncertainty and encoder version.
Primary + backup executorExecute overlapping grasp and recovery skills with different approach strategies.Capability, chosen skill, action owner, progress and observed outcome.
CoordinatorRetrieve similar episodes; choose an eligible controller; request fresh evidence.Retrieved examples, selection score, observation age and reason for takeover.

Research teamDiagnose failures, propose a small policy edit, test it and decide whether to retain it.Candidate diff, paired comparison, rejected candidates and held-out results.

Only agents with the required skill can take over. An obstacle observer cannot replace a grasp executor just because both share a memory.

Shared memory is an interface.

Store object identity, pose and frame, timestamp, source, confidence, action ownership, attempted skill and outcome. Retrieve descriptions or embeddings, but validate the current state before using a remembered action.

MoE is a related architecture.

A neural mixture of experts routes activations through parameterized experts. Our first demo routes control between software skills. CoRE is a closer learned robotics precedent; InstAgent is closer to the shared-memory software-team design.

CoRE · InstAgent. Neither makes arbitrary faults recoverable.

04 / A laptop-sized experiment

Separate controller faults from shared-information faults.

The implemented pilot compares one scripted controller, takeover by an identical backup, takeover with timestamp-triggered observation refresh, and takeover with periodic refresh. The same reset seed, fault time and action horizon are used in each comparison.

Injected conditionQuestion it isolatesExpected diagnostic
Healthy controlDoes supervision interfere with a working controller?Task success, unnecessary switches and refresh cost.

Shared object-pose publisher stopsDo backups inherit the same stale belief?Takeover versus independent observation refresh.
Publisher and refresh sensor both failDoes the repair depend on a functioning information source?Common-sensor negative control.
Implemented measurement: task success, reset pairing, deterministic replay, action bounds, takeover counts, refresh counts and an offline cosine diagnostic. All measured outcomes and limitations are in the findings report.

Next learned comparison: collect recovery outcomes on development scenarios, then freeze four routing rules: fixed backup, cosine-nearest experience, recovery-outcome calibration, and calibrated routing with freshness checks. Give every rule the same observations, retry allowance and compute budget. Freeze the final choice before evaluating new poses, objects and fault times.

A useful embeddings baseline is RouterVLA: semantic retrieval plus historical and probe outcomes. Its replay evaluation is not evidence of mid-trajectory takeover.

05 / Use your embeddings background

Compare the same situations across checkpoints.

Fix the examples before comparing representations.

For the neuron study, preserve token IDs, marked positions and windows from early, lithium-heavy, late and held-out contexts. For robotics, preserve exact simulator observations and action histories. Compare the response vector across the whole panel, not the cosine of one scalar.

Separate geometry, scale and input changes.

Measure raw and centered cosine, norms, ranks, gate/up inputs and output contribution. For robot memory, compare global embeddings with task-coordinate error and current affordances. Do not mix encoder versions without testing alignment on separate data.

Ask whether the representation predicts an action outcome.

Use held-out recovery outcomes and paired interventions. A stable probe, high cosine or stable subspace means information is recoverable under that test; it does not establish that the controller uses it causally.

06 / The self-improvement connection

Retain a tested coordination change.

A diagnostic agent proposes a small executable change to routing or memory validation. An experiment agent evaluates it on paired development cases; a critic checks budget parity and regressions. Retain the change only if it passes a predefined criterion, then evaluate the frozen selected version once on untouched cases.

Claim boundary: temporary memory updates are adaptation. A persistent change with better held-out coordination is program improvement. Improving the system's ability to generate future improvements requires another measurement. This pilot runs fixed policies and demonstrates none of those improvement loops.

Compare the proposed research team with equal-budget random or simple manual policy search. Log failed candidate edits as well as successful ones, so more attempts cannot masquerade as better reasoning.

07 / A 48-hour build

Make the evidence the demo.

Hours 0–12

Working baseline

Reproduce the provided pilot, inspect actual traces, and implement two recovery strategies. Lock faults, observation interface and metrics.

Hours 12–30

Routing experiment

Collect development outcomes. Compare cosine routing with outcome-calibrated routing and simple baselines. Add mixed fault timing without tuning on final cases.

Hours 30–48

Tested revision

Allow one small persistent coordinator edit. Evaluate on untouched cases and present successes, failures and cost together. Add another arm only if this pipeline is stable.

The November 14–15 AI Research Hackathon lists AI Scientist Swarms and self-improvement tracks. This project fits the former immediately as a proposed experimental workflow; the latter requires retained, evaluated improvements. Laptop CPU suffices for the measured scripted pilot. Learned encoders or model agents may need cloud inference.

08 / Five questions for Abay

Questions that could change the project

  1. Which Borrowed Geometry policy checkpoint, trained interface and exact evaluation script could we use to replace the scripted oracle in this fault harness?
  2. Would you predict that shared representation geometry improves takeover, or that shared upstream errors make controllers fail together? What intervention would distinguish those predictions?
  3. Your weight pipeline already computes cosine-related quantities. Can we obtain complete records and exact fixed windows to distinguish task-aligned weight changes from changing upstream inputs?
  4. When lithium stops ranking highly at L03N6372+, does a lithium-discriminating population or subspace remain, and can a causal intervention test its use?
  5. What smallest retained coordination change would count as improvement for this collaboration, and which untouched evaluation, budget and regression criterion would falsify the claim?
